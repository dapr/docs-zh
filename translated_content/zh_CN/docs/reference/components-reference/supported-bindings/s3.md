## component 格式

要设置 AWS S3 binding，请创建一个类型为 `bindings.aws.s3` 的 component。该 binding 也适用于其他兼容 S3 的服务，例如 Minio。有关如何创建和应用 binding 配置，请参阅[此指南]({{% ref "howto-bindings.md#1-create-a-binding" %}})。

有关身份验证相关属性的信息，请参阅[对 AWS 进行身份验证]({{% ref authenticating-aws.md %}})。

```yaml
apiVersion: dapr.io/v1alpha1
kind: Component
metadata:
  name: <NAME>
spec:
  type: bindings.aws.s3
  version: v1
  metadata:
  - name: bucket
    value: "mybucket"
  - name: region
    value: "us-west-2"
  - name: endpoint
    value: "s3.us-west-2.amazonaws.com"
  - name: accessKey
    value: "*****************"
  - name: secretKey
    value: "*****************"
  - name: sessionToken
    value: "mysession"
  - name: decodeBase64
    value: "<bool>"
  - name: encodeBase64
    value: "<bool>"
  - name: forcePathStyle
    value: "<bool>"
  - name: disableSSL
    value: "<bool>"
  - name: insecureSSL
    value: "<bool>"
  - name: storageClass
    value: "<string>"
```

{{% alert title="警告" color="warning" %}}
上面的示例以明文字符串的形式使用了 secrets。建议按照[此处]({{% ref component-secrets.md %}})所述，为这些 secrets 使用 secret store。
{{% /alert %}}

## 规范 metadata 字段

| 字段 | 是否必需 | binding 支持 | 详细信息 | 示例 |
|--------------------|:--------:|------------|-----|---------|
| `bucket` | Y | 输出 | 要写入的 S3 存储桶名称 | `"bucket"` |
| `region`             | Y        | 输出 |  特定的 AWS 区域 | `"us-east-1"`       |
| `endpoint`           | N        | 输出 |  特定的 AWS 端点 | `"s3.us-east-1.amazonaws.com"` |
| `accessKey`          | Y        | 输出 | 用于访问此资源的 AWS 访问密钥                              | `"key"`             |
| `secretKey`          | Y        | 输出 | 用于访问此资源的 AWS Secret Access Key                       | `"secretAccessKey"` |
| `sessionToken`       | N        | 输出 | 要使用的 AWS 会话令牌                                            | `"sessionToken"`    |
| `forcePathStyle`     | N        | 输出 | 目前 Amazon S3 SDK 支持虚拟托管式和路径式访问。`"true"` 为路径式格式，例如 `"https://<endpoint>/<your bucket>/<key>"`。`"false"` 为托管式格式，例如 `"https://<your bucket>.<endpoint>/<key>"`。默认为 `"false"` | `"true"`, `"false"` |
| `decodeBase64` | N | 输出 | 在将文件内容保存到存储桶之前对 base64 文件内容进行解码的配置（用于保存二进制内容的文件）。`"true"` 是唯一允许的肯定值，`"True", "1"` 等其他肯定形式不可接受。默认为 `false` | `"true"`, `"false"` |
| `encodeBase64` | N | 输出 | 在返回内容之前对文件内容进行 base64 编码的配置（用于打开二进制内容的文件）。`"true"` 是唯一允许的肯定值，`"True", "1"` 等其他肯定形式不可接受。默认为 `"false"` | `"true"`, `"false"` |
| `disableSSL`     | N        | 输出 | 允许连接到非 `https://` 端点。默认为 `"false"` | `"true"`, `"false"` |
| `insecureSSL`     | N        | 输出 | 连接到 `https://` 端点时，接受无效或自签名的证书。默认为 `"false"` | `"true"`, `"false"` |
| `storageClass` | N | 输出 | 创建操作期间对象所需的 storage class。[有效的 AWS storage class 可在此处查看](https://aws.amazon.com/s3/storage-classes/) | `STANDARD_IA` |

{{% alert title="重要" color="warning" %}}
在 EKS（AWS Kubernetes）上与应用程序一起运行 Dapr sidecar（daprd）时，如果您使用的节点或 Pod 已关联了定义 AWS 资源访问权限的 IAM 策略，则**不得**在所用 component 规范的定义中提供 AWS 访问密钥、秘密密钥和令牌。
{{% /alert %}}

### 与 Minio 一起使用

[Minio](https://min.io/) 是一种将本地存储暴露为兼容 S3 的块存储的服务，在开发环境中常被用作 S3 的替代方案。您也可以在 S3 binding 中使用 Minio，但需要做一些配置调整：
1. 将 `endpoint` 设置为 Minio 服务器的地址，包括协议（`http://` 或 `https://`）以及末尾可选的端口。例如 `http://minio.local:9000`（具体取值取决于您的环境）。
2. `forcePathStyle` 必须设置为 `true`。
3. `region` 的值并不重要，您可以将其设置为 `us-east-1`。
4. 根据您的环境，如果您使用非安全连接（`http://` 协议）连接 Minio，可能需要将 `disableSSL` 设置为 `true`。如果您使用安全连接（`https://` 协议）但证书是自签名的，可能需要将 `insecureSSL` 设置为 `true`。

{{% tab "LocalStack" %}}
为便于本地开发，可以使用 [LocalStack 项目](https://github.com/localstack/localstack)集成 AWS S3。请按照[这些说明](https://github.com/localstack/localstack#running)运行 LocalStack。

要使用 Docker 从命令行在本地运行 LocalStack，请使用类似下面的 `docker-compose.yaml`：

```yaml
    image: localstack/localstack:1.4.0
    ports:
      - "127.0.0.1:4566:4566"
    environment:
      - DEBUG=1
      - DOCKER_HOST=unix:///var/run/docker.sock
    volumes:
      - "<PATH>/init-aws.sh:/etc/localstack/init/ready.d/init-aws.sh"  # 初始化钩子
      - "${LOCALSTACK_VOLUME_DIR:-./volume}:/var/lib/localstack"
      - "/var/run/docker.sock:/var/run/docker.sock"
```

要使用 S3 component，您需要使用一个已存在的存储桶。上面的示例使用了 [LocalStack 初始化钩子](https://docs.localstack.cloud/references/init-hooks/)来设置存储桶。

要在 S3 binding 中使用 LocalStack，需要在 component metadata 中提供 `endpoint` 配置。连接生产环境的 AWS 时不需要 `endpoint`。


```yaml
apiVersion: dapr.io/v1alpha1
kind: Component
metadata:
    name: aws-s3
    namespace: default
spec:
  type: bindings.aws.s3
  version: v1
  metadata:
    - name: bucket
      value: conformance-test-docker
    - name: endpoint
      value: "http://localhost:4566"
    - name: accessKey
      value: "my-access"
    - name: secretKey
      value: "my-secret"
    - name: region
      value: "us-east-1"
```

## binding 支持

此 component 支持**output binding**，并提供以下操作：

- `create`：[创建对象](#创建对象)
- `get`：[获取对象](#获取对象)
- `delete`：[删除对象](#删除对象)
- `list`：[列出对象](#列出对象)
- `bulkGet`：[批量获取对象](#批量获取对象)
- `bulkCreate`：[批量创建对象](#批量创建对象)
- `bulkDelete`：[批量删除对象](#批量删除对象)

### 创建对象

要执行创建操作，请使用 `POST` 方法调用 AWS S3 binding，并提供以下 JSON 请求体：

> 注意：默认会生成一个随机 UUID。关于使用 metadata 设置名称，请参阅下文。

```json
{
  "operation": "create",
  "data": "YOUR_CONTENT",
  "metadata": { 
    "storageClass": "STANDARD_IA",
    "tags": "project=sashimi,year=2024",
  }
}
```

例如，在使用 Linux curl 命令执行 `create` 操作时，您可以提供 storage class 或标签：

```bash
curl -d '{ "operation": "create", "data": "YOUR_BASE_64_CONTENT", "metadata": { "storageClass": "STANDARD_IA", "project=sashimi,year=2024" } }' /
http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
```

### 列出对象

要执行列出对象操作，请使用 `POST` 方法调用 S3 binding，并提供以下 JSON 请求体：

```json
{
  "operation": "list",
  "data": {
    "maxResults": 10,
    "prefix": "file",
    "marker": "hvlcCQFSOD5TD",
    "delimiter": "i0FvxAn2EOEL6"
  }
}
```

data 参数如下：

- `maxResults`：（可选）设置响应中返回的最大键数量。默认情况下，该操作最多返回 1,000 个键名。响应中的键可能更少，但绝不会更多。
- `prefix`：（可选）将响应限制为以指定前缀开头的键。
- `marker`：（可选）Amazon S3 开始列出的位置标记。Amazon S3 会从该指定键之后开始列出。marker 可以是存储桶中的任意键。
 随后的调用可以使用该 marker 值请求下一组列表项。
- `delimiter`：（可选）分隔符是用于对键进行分组的字符。


#### 响应

响应体包含找到的对象列表。

对象列表以 JSON 数组的形式返回，格式如下：

```json
{
	"CommonPrefixes": null,
	"Contents": [
		{
			"ETag": "\"7e94cc9b0f5226557b05a7c2565dd09f\"",
			"Key": "hpNdFUxruNuwm",
			"LastModified": "2021-08-16T06:44:14Z",
			"Owner": {
				"DisplayName": "owner name",
				"ID": "owner id"
			},
			"Size": 6916,
			"StorageClass": "STANDARD"
		}
	],
	"Delimiter": "",
	"EncodingType": null,
	"IsTruncated": true,
	"Marker": "hvlcCQFSOD5TD",
	"MaxKeys": 1,
	"Name": "mybucketdapr",
	"NextMarker": "hzaUPWjmvyi9W",
	"Prefix": ""
}
```

### 批量获取对象

要并行下载多个对象，请使用 `POST` 方法调用 AWS S3 binding，并提供以下 JSON 请求体：

```json
{
  "operation": "bulkGet",
  "data": {
    "items": [
      { "key": "file1.txt" },
      { "key": "file2.txt" },
      { "key": "file3.txt", "filePath": "/tmp/file3.txt" }
    ],
    "concurrency": 5
  }
}
```

data 参数如下：

- `items`：（必需）要下载的对象数组。每一项包含：
  - `key`：（必需）S3 对象的名称。
  - `filePath`：（可选）如果提供，对象将直接流式写入此本地文件路径，而不是在响应体中返回。
- `concurrency`：（可选）最大并发下载数。默认为 `10`，且必须大于 `0`。

component 级的 `encodeBase64` metadata 选项适用于批量获取。设置为 `"true"` 时，对象内容会先进行 base64 编码，再在响应体中返回。指定 `filePath` 时，文件将包含 base64 编码的文本，而不是原始字节。

#### 示例

{{< tabpane text=true >}}

  {{% tab "Windows" %}}
  ```bash
  curl -d "{ \"operation\": \"bulkGet\", \"data\": { \"items\": [{ \"key\": \"file1.txt\" }, { \"key\": \"file2.txt\" }], \"concurrency\": 5 } }" http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
  ```
  {{% /tab %}}

  {{% tab "Linux" %}}
  ```bash
  curl -d '{ "operation": "bulkGet", "data": { "items": [{ "key": "file1.txt" }, { "key": "file2.txt" }], "concurrency": 5 } }' \
        http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
  ```
  {{% /tab %}}

{{< /tabpane >}}

#### 响应

响应体包含一个 JSON 数组，其中为每个请求的项提供一个结果。每个结果都包含按项的错误字段，以实现部分失败语义：整体操作成功，单个键的失败会分别报告：

```json
[
  { "key": "file1.txt", "data": "contents of file1" },
  { "key": "file2.txt", "data": "contents of file2" },
  { "key": "missing.txt", "error": "object not found" }
]
```

为某项指定 `filePath` 时，将省略 `data` 字段，并将内容写入指定的文件。

### 批量创建对象

要并行上传多个对象，请使用 `POST` 方法调用 AWS S3 binding，并提供以下 JSON 请求体：

```json
{
  "operation": "bulkCreate",
  "data": {
    "items": [
      { "key": "file1.txt", "data": "Hello World" },
      { "key": "file2.txt", "data": "Another file", "contentType": "text/plain" },
      { "key": "file3.txt", "filePath": "/path/to/local/file.txt" }
    ],
    "concurrency": 5
  }
}
```

data 参数如下：

- `items`：（必需）要上传的对象数组。每一项包含：
  - `key`：（必需）S3 对象的名称。
  - `data`：要上传的内容。`data` 或 `filePath` 必须至少提供一个。
  - `filePath`：要上传的本地文件路径。`data` 或 `filePath` 必须至少提供一个。
  - `contentType`：（可选）对象的 MIME 类型。
- `concurrency`：（可选）最大并发上传数。默认为 `10`，且必须大于 `0`。

component 级的 `decodeBase64` metadata 选项适用于批量创建。设置为 `"true"` 时，输入内容会在上传到 S3 之前先进行 base64 解码。这同时适用于内联的 `data` 字段，以及从 `filePath` 读取的内容。仅当文件本身包含 base64 编码内容时，才应将 `filePath` 与 `decodeBase64` 一起使用。

#### 示例

{{< tabpane text=true >}}

  {{% tab "Windows" %}}
  ```bash
  curl -d "{ \"operation\": \"bulkCreate\", \"data\": { \"items\": [{ \"key\": \"file1.txt\", \"data\": \"Hello World\" }, { \"key\": \"file2.txt\", \"data\": \"Another file\" }] } }" http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
  ```
  {{% /tab %}}

  {{% tab "Linux" %}}
  ```bash
  curl -d '{ "operation": "bulkCreate", "data": { "items": [{ "key": "file1.txt", "data": "Hello World" }, { "key": "file2.txt", "data": "Another file" }] } }' \
        http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
  ```
  {{% /tab %}}

{{< /tabpane >}}

#### 响应

响应体包含一个 JSON 数组，其中为每一项提供一个结果，包括已创建对象的位置或按项的错误：

```json
[
  { "key": "file1.txt", "location": "https://mybucket.s3.us-west-2.amazonaws.com/file1.txt" },
  { "key": "file2.txt", "location": "https://mybucket.s3.us-west-2.amazonaws.com/file2.txt" },
  { "key": "bad-file.txt", "error": "either data or filePath is required" }
]
```

### 批量删除对象

要在一次批处理操作中删除多个对象，请使用 `POST` 方法调用 AWS S3 binding，并提供以下 JSON 请求体：

```json
{
  "operation": "bulkDelete",
  "data": {
    "keys": ["file1.txt", "file2.txt", "file3.txt"]
  }
}
```

data 参数如下：

- `keys`：（必需）要删除的对象键名数组。必须至少包含一个键。

批量删除使用 S3 的 [DeleteObjects](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObjects.html) 批处理 API。如果提供的键超过 1,000 个，请求将自动拆分为每批 1,000 个键的多个批次。

#### 示例

{{< tabpane text=true >}}

  {{% tab "Windows" %}}
  ```bash
  curl -d "{ \"operation\": \"bulkDelete\", \"data\": { \"keys\": [\"file1.txt\", \"file2.txt\"] } }" http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
  ```
  {{% /tab %}}

  {{% tab "Linux" %}}
  ```bash
  curl -d '{ "operation": "bulkDelete", "data": { "keys": ["file1.txt", "file2.txt"] } }' \
        http://localhost:<dapr-port>/v1.0/bindings/<binding-name>
  ```
  {{% /tab %}}

{{< /tabpane >}}

#### 响应

响应体包含一个 JSON 数组，其中为每个键提供一个结果，并带有按项的错误字段，以实现部分失败语义：

```json
[
  { "key": "file1.txt" },
  { "key": "file2.txt" },
  { "key": "no-permission.txt", "error": "Access Denied" }
]
```

空的 `error` 字段（或不存在该字段）表示删除成功。
