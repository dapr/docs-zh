分布式应用通常由许多微服务组成，其实例数量可达数十个，有时甚至数百个，并在底层基础设施上扩缩容。随着这些分布式解决方案的规模和复杂性不断增加，系统发生故障的可能性也不可避免地随之增加。服务实例可能因各种问题而发生故障或变得无响应，包括硬件故障、异常吞吐量，或扩容和应用重启等应用生命周期事件。设计并实现一种能够检测、缓解并应对故障的自愈解决方案至关重要。

## 弹性策略
{{< diagram resiliency-policies >}}

Dapr 提供定义并将容错弹性策略应用于应用的能力。你可以为以下弹性模式定义策略：

- 超时
- 重试/退避
- 熔断器

使用[弹性规范]({{% ref resiliency-overview %}})调用组件时，这些策略可以应用于任何 Dapr API 调用。

## 应用健康检查
{{< diagram name="app-health" width="85" >}}

应用可能因多种原因而变得无响应。例如，应用可能忙于处理现有工作而无法接受新工作、可能已经崩溃，或处于死锁状态。这种情况有时是暂时的，有时则会持续存在。

Dapr 提供通过探针监控应用健康状况的功能，探针会检查应用的健康状况，并对状态变化做出响应。检测到应用不健康时，Dapr 将停止代表该应用接受新工作。

了解如何为你的应用启用[应用健康检查]({{% ref app-health %}})。

## 边车健康检查
{{< diagram name="sidecar-health" width="85" >}}

Dapr 提供了一种通过 [HTTP `/healthz` 端点]({{% ref health_api %}})确定自身健康状况的方式。通过此端点，可以对 *daprd* 进程（即边车）执行以下操作：

- 探测其健康状况
- 确定其就绪状态和存活状态

了解如何为你的应用启用 [Dapr 健康检查]({{% ref sidecar-health %}})。
